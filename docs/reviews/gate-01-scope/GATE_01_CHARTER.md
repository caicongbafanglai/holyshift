## 1. 阶段目标与范围

### 1.1 目标

判断 `HS-MVP-1.0` 的目标玩家、核心承诺、Must/Should/Won't、人员容量、预算、平台、依赖、风险和删减方案是否足以支持受控开发，并冻结一个可回退的范围基线。

### 1.2 范围内

- 现代桌面浏览器、低多边形 3D 自由探索、双视角、单机、1v1 回合制战斗的产品定义。
- `20–35` 分钟完整流程与需求候选第 4 节 Must/Should 工作量。
- 实际人员、产能、预算、设备、浏览器、托管、许可与玩家/评审资源。
- 20 个实施周、Gate 2/3 的玩家证据周、穿插其间的正式评审窗口、依赖、风险、16% 删减和失败退路。
- Gate 1 前最多 2 个 DEV 人日的可丢弃估算 spike（仅在本章程预登记后允许）。

### 1.3 范围外

- 对当前实现作正式 Gate PASS 宣告；实现提交与测试可作为后续候选证据，但不能替代独立席位、真实设备和真人玩家材料。
- Gate 2 战斗白模、试玩结果、性能达标或发布结论。
- 即时动作战斗、大型开放世界、复杂物理、移动端、账号/云档、多人、商业化及需求文档其余 Won't 项。

### 1.4 候选版本与回退点

- 被审版本：包含候选需求、治理制度与本章程的同一目标提交；其准确 SHA 由目标提交之后生成的 `EV-G1-010` 冻结记录绑定，不修改目标提交。

## 6. 冻结指标与风险预算

### 6.1 产品与平台指标

- 目标玩家、核心承诺、Must/Should/Won't：以 `EV-G1-002` 为准。
- 目标环境：支持 WebGL2、IndexedDB 与 Web Locks 的现代桌面 Chrome/Edge、Firefox、Safari，基准窗口及参考机；准确设备由 `EV-G1-006` 冻结。
- 体验时长：`20–35` 分钟。
- 候选实施量：Must `42` DEV 人日、Should `8` DEV 人日。
- 候选删减：`8/50 = 16%`。
- 容量门槛：真实角色分池后，每个不可替代资源和整体计划都不得超过确认产能的 `80%`。
- 日历边界：`20` 个实施周不包含 Gate 2/3 的两个 T0 前玩家证据周或 Gate 2–8 的七个 `T0–T+4` 窗口；从 Gate 1 `T0` 起的无延期最短候选历时为 `30` 个日历周。

### 6.2 Gate 1 P0/P1

沿用治理制度通用定义，并冻结以下阶段实例：

- `P0`：伪造/隐瞒人员、预算、许可或证据；核心范围依赖明确不可取得的法律/资金/平台条件；候选方案存在已确认且不可恢复的数据、安全或合规阻断。
- `P1`：目标玩家或核心循环仍不明确；任一 Must 缺真人负责人、估算或验收；范围超过确认产能 80%；战斗范式/平台/存档等关键决策未定；关键人员、设备、资金、版权或验证计划未确认。

当前 `EV-G1-004/005/006/011` 缺失，因此候选材料不得进入 READY；这不是已启动评审后的 P1 裁决。

### 6.3 P2/P3 风险点算法

- 每个未关闭 `P2` 计 `2` 点，每个未关闭 `P3` 计 `1` 点。
- Gate 1 总上限 `6` 点；单个事实域上限 `3` 点。
