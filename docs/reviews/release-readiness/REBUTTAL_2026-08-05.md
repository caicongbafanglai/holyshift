# 对 2026-08-02 两份报告的事实反驳

结论先说：发布审查的“不放行”方向正确，但它不是委员会裁决；Nuclei 报告的
“在限定边缘扫描中未命中高危”可以成立，“全量安全检查”不能成立。

1. 没有 14 席、独立性矩阵、当前范围的有效冻结章程、密封评分和真人证据，
   就无权写“七域一致”或“委员会 DEFER”。仓库虽有历史 Gate 1 草案，但它未进
   READY；正式状态只能是 `NOT-STARTED / DRAFT`。P2/P3 也只是审计建议级别，
   不是法定定级。
2. “已确认 P0/P1 为 0”已被复测推翻。固定基线存在最终击杀刷新后永久卡关、
   键盘 Enter/Space 无法开始、未来版本主档被旧备份静默覆盖等核心问题。
   它们至少是发布阻断，卡关按制度还是 P0 候选；相关 AI/共享环境证据只能算
   一个相关来源，不能伪造法定双确认。
3. “Cloudflare 隐藏源站”与事实相反：两个外部网络可绕过边缘直接访问 HTTP
   源站，未知 Host 也得到站点；边缘到源站还是明文。为避免扩大攻击面，公开
   仓库不记录源站地址，取证由授权运维人员线下保管。
4. Nuclei 请求数不是覆盖证明。本次复查未获得附录所列原始 JSONL，也未获得
   完整命令、模板哈希和 OAST 记录；报告还明确排除了源站、认证、业务逻辑、
   DoS 和未知漏洞。准确表述只能是“2026-08-02 对 Cloudflare 公开边缘、给定
   模板及排除项未确认高危”。
5. “最新 Nuclei v3.8.0”是可证伪的宣传：官方已在 2026-07-06 发布
   [v3.11.0](https://github.com/projectdiscovery/nuclei/releases/tag/v3.11.0)。落后
   版本不抹掉已复现的 HTTP/TLS 事实，却足以击穿“最新、全量”的包装。
6. Nuclei 的修复优先级 `P1` 与治理制度的缺陷严重度 `P1` 不是同一量表，混用
   会制造虚假的定级精度。

所以，不能用扫描器的零高危给发布背书，也不能用不存在的委员会给拒绝结论
镀金。能站得住的只有可复现事实：该基线不应发布，整改后仍须真人委员会、
目标设备和外部基础设施重新验收。
